# V12 · 控制台前端优化设计

> 站点: `being.luxera.top`(仓 `simulation-agent-platform`,前端 `frontend/`)
> 判断标准: 这个产品要接近"我们希望的它"的样子 —— 每个 agent 是一个**仿真的人**,
> 有身体、有生活、有心灵, 有自己的手机和自己的聊天软件。
>
> 上游文档: `V2.2-detailed-design.md`(认知链)、`V11-persistent-world-driven-runtime.md`(运行期)、
> `V11-implementation-plan.md`。**这份文档是它们的读面** —— 前两份描述"她是怎么运转的",
> 这一份描述"人怎么看见她在运转"。

## 1 现状盘点

### 1.1 仓 2 · 控制台(`being.luxera.top`)

| 项 | 现状 |
| --- | --- |
| 规模 | `src/` 下 49 个文件, 约 **10 385 行** TS/TSX |
| 路由 | `src/lib/routes.ts` 的 `SPA_PATHS`, 7 条静态路径 + `/agents/:agentId` |
| 页面 | `Dashboard` `/`、`Agents` `/agents`、`AgentDetail`(8 个标签页)、`Applications`、`ApiPortal`、`Clients`、`Connect`、`Docs`、`System` |
| 状态 | Zustand 5(`stores/session.ts`、`stores/theme.ts`) |
| 样式 | Tailwind 3.4, `darkMode: 'class'`, **全项目零 `dark:` 前缀** —— 只有语义 token |
| 测试 | 9 个测试文件 / 236 条, `environment: 'node'`, **不能测 JSX 结构** |
| 取数 | `src/lib/studio.ts` 的 `SECTIONS` 表驱动 8 个标签页里的 6 个 |

**盘点结论 —— 问题都是具体的:**

1. **运维面没有页面。** `GET /api/v10/events`、`/api/meta/*`、`/api/v9/*` 这些端点在
   前端**零调用点**。想看一眼"世界往她那儿递了什么", 只能开命令行。
2. **标签页里混着两个层次的东西。** `relationship` 那一页同时画"她对这个人的十条维度"
   (她的内部状态)与"Reality Ledger 投影"(账本, 权威事实), 而两者**可以互相矛盾** ——
   矛盾恰恰是最该被看见的一件事, 却没有任何地方说明它们是两组数。
3. **原始 JSON 曾经是主要画法。** 重做前 `overview` 是一屏 JSON; 现在收敛到了
   `archive`。但 `relationship` 页里"关系维度"仍是一块原始 JSON, 而它 **比同一个
   数据用 `Meter` 画出来的版本更显眼** —— 同一份数据画两遍, 丑的那一遍排在前面。
4. **侧栏是一串平铺的项。** `NAV` 是一个数组, 7 项没有分组。于是"看她"的两个页面
   与"换 API 客户端钥"的页面在视觉上是同一类东西。
5. **`/events` 与 `/runtime` 两个路径不存在**, 而 `routes.ts` 已经为它们写好了
   `collidesWithBackend()` 的检查 —— 检查在那儿, 被检查的东西不在。

### 1.2 仓 1 · 聊天前端(`chat.luxera.top`)

| 项 | 现状 |
| --- | --- |
| 规模 | `src/` 下 100+ 个文件, 约 **17 118 行** TS/TSX |
| 路由 | `routes.tsx` 的 `tabRoutes`(4 tab) + `fullScreenRoutes`(全屏, 无 tab bar) |
| 页面 | 聊天列表 / 聊天室 / 通讯录 / 资料页 / Agent 设置 / 发现 / 应用 / 会话 / 我(提醒·通知·账号ID) |
| 测试 | 37 个测试文件 / 463 条 |
| 测试能力 | **比仓 2 强**: `renderToStaticMarkup` 可用, 组件结构可断言 |

**盘点结论:**

1. **`setMuted` / `setPinned` 有实现, 零调用点。** `src/api/conversations.ts` 里
   两个函数写完了, 界面上**没有任何入口**。这意味着产品原话里最硬的那一条
   ——"每条消息按用户在聊天软件里设的通知规则决定要不要通知她"—— 在 UI 上是不可
   表达的: 用户没法设免打扰, 于是"她怎么不回我"永远不会有一个诚实的答案。
2. **"我把它设成免打扰了"这件事没有痕迹。** 即使补上开关, 那个开关只在打开那一段
   对话时才看得见 —— 而人不会没事去点开一段他没在等的对话。忘记才是这个功能真正
   的故障形态。
3. **页头副标题只写"仿真 Agent"。** 一句恒定的类型说明, 占着最贵的一行位置。

### 1.3 设计系统(两个前端共用)

`tailwind.config.js` 与 `src/index.css` 在两个仓里**逐字相同**。不是"抄一份保持一致",
是同一个定义写了两处, 因为两个前端属于同一个产品, 而"同步"这件事只要靠人去记,
就一定会漂 —— 漂的表现是某个按钮在两个站点里是两种蓝, 那种错误没人会报告,
但所有人都会觉得哪里不对。

**核心决策: 语义 CSS 变量 + `darkMode: 'class'`, 组件只用语义名, 全项目零 `dark:` 前缀。**
于是双主题的成本是每个概念**一个类名**, 而不是每个类名两遍。

## 2 信息架构: 两拨人, 不在一页里

### 2.1 判据

这一节只有一条规则, 其余都是它的推论:

> **一页只对一拨人说话。看她和运维她的人不在同一页里。**

理由是这两拨人问的问题**没有交集**:

| 看她的人 | 运维 / 开发 |
| --- | --- |
| 她今天在做什么? | 世界往她那递了几条事件? |
| 她为什么没回我? | 那几条为什么没进感知? |
| 她跟这个人熟吗? | 影子对比跑没跑? 降级了几次? |
| 她身体难受吗? | 认知链这一小时调了多少次模型? |

"她今天在做什么"和"这一小时调了多少次模型"并排放在一屏里, 后果不是"信息有点多",
而是**前者会被后者吃掉** —— 一个想知道她好不好的人, 看到 `traces` 与 `metrics`
的第一反应是"这不是给我的", 然后关掉。

### 2.2 第一层: 看她的人

```
/                      总览 · 这台机器上有几个她, 各自醒着还是睡着
/agents                她是谁(名单)
/agents/:agentId       她 —— 八个标签页, 见 §2.4
```

**`/` 回答的问题**: "现在有几个 agent, 她们在跑吗?"
**它不该回答**: 任何计数器的具体数值。那是 `/runtime` 的事。

### 2.3 第二层: 运维 / 开发

```
/events                事件流 —— 世界往她那儿递了什么(§5)
/runtime               运行时 —— 认知链的计数、轨迹、排程、影子对比(§5.5)
/applications          应用目录 —— 她能玩什么(LAP 能力树)
/access                API —— 开放面与客户端钥
/system                平台自身的健康
```

五页的分工是**按"你在排查什么"分的**, 不是按数据源分的:

| 页面 | 唯一回答的问题 |
| --- | --- |
| `/events` | 她那边**收到了什么**(输入侧) |
| `/runtime` | 她那边**拿它做了什么**(处理侧) |
| `/applications` | 平台**能给她什么** |
| `/access` | 谁**能调这个平台** |
| `/system` | 平台**自己还好吗** |

输入侧与处理侧必须分开, 因为一个"她没反应"的故障有且只有两种可能: 事件没到
(`/events` 空), 或者到了但没被处理(`/events` 有、`/runtime` 没有对应轨迹)。
把它们放在同一页, 排查的人要在一屏里追两条时间线, 而这两条时间线的时钟**不是同一个**。

### 2.4 八个标签页的分半

`AGENT_TABS` 的顺序是**一条问问题的顺序**, 不是排版偏好:

```
前四个 —— 她此刻:  今天 · 计划表 · 手机 · 身体
后四个 —— 她是谁:  关系网 · 记忆 · 心智 · 档案
```

前四个是快的、看得见变化的, 回答"她好吗"; 后四个是慢的、累积的, 回答"她是谁"。
混排就会出现"她的态度"和她的 `intimacy` 字段并排摆在一屏里。

`档案` 是刻意留下的那个"丑"页: 原始 JSON 没有消失, 它被**收敛**到最后一个标签页。
界面上一旦有两处能看见原始返回体, 每一页都会退化成 JSON 查看器。

### 2.5 这条规则怎么被机器钉住

```ts
// lib/routes.ts —— 表里的顺序就是侧栏的顺序, 也是那张两栏分组的顺序
export const SPA_PATHS = {
  dashboard: '/', agents: '/agents',                       // ← 看她的人
  events: '/events', runtime: '/runtime',                  // ← 运维 / 开发
  applications: '/applications', access: '/access', system: '/system',
} as const
```

```ts
// components/Layout.tsx
const NAV_GROUPS = [
  { id: 'her', label: '看她', items: [...] },
  { id: 'ops', label: '运维 / 开发', items: [...] },
] as const
```

侧栏在 `md` 以下不显示分组标题, 只画一条竖分隔线 —— 小屏上两行标题比七个入口还占地方,
而分组的**视觉**效果在窄屏本来也弱。

`routes.test.ts` 断言的是"SPA 路径不许落在 `/api/**` 之下", 因为控制台与后端同源,
`/api/**` 是后端独占前缀: 一个挂在它下面的页面只在客户端跳转时正常, 直接访问或刷新
时浏览器发的是 document 请求, 被 nginx 交给后端, 页面代码一行都没跑。

### 2.6 AgentPicker: 运维页没有 id 的那个问题

`/events` 与 `/runtime` 的每一个端点都是**按 companion** 的, 而这两条路径里没有 id。

三种做法里选了一种:

| 做法 | 为什么不是它 |
| --- | --- |
| 空着等用户选 | 进来是一屏"请先选择", 而那些数就在那儿, 只是没显示 |
| 默认第一个, 不说选了谁 | 地址栏上是 `/events`, 屏幕上是丙的数据, 复制链接给别人是另一份数据 |
| **URL 上的 `?agent=`, 缺省时把 fallback 写回 URL** | ✅ |

`useAgentChoice()` 做第三件事: 读 `?agent=`, 缺省取第一个 companion, 并**把兜底值写回
URL**。于是"我看到的是谁"和"地址栏写的是谁"永远是同一个答案, 而用户一次点击都不用做。

## 3 「她的一天」怎么画 —— 时间段, 不是点

### 3.1 计划表是时间窗

`PlanItem` 上是 `TimeWindow` + `expectedDuration`, 不是 `startAt` 一个瞬时点。
"12:00 做作业 1 小时"是一条**横条**, 不是 12 点上的一个标记。

画成点会立刻产生三个说不通的地方:

- 12:00 到 13:00 之间她在干嘛? 点上没有信息。
- 两条 12:00 的计划怎么摆? 叠在一起, 分不清是冲突还是并列。
- "现在"落在一条计划的中间时, 怎么表示"正在进行"? 点上没有长度, 只能换一种颜色,
  而颜色在 §5 已经被三类事件用掉了。

### 3.2 三种形状

三类事件的视觉编码**首要是形状**, 颜色是第二位的(§10.4):

| 类别 | 接口 | 形状 | 为什么 |
| --- | --- | --- | --- |
| A 持续影响 | `StateEffectEvent` | **半透明色带**, 从发生一直铺到"现在" | 没有结束时间 —— 它一直在生效, 直到某个动作把它消掉 |
| B 实时感官 | `SensoryEvent` | 轨道**下方**一根针 | 它不占用时间, 只占用一个时刻 |
| C 计划表 | `ScheduledEvent` | 轨道**上**一根横条 | 有开始也有结束, 属于时间轴 |

A 类的带子画到 `now` 而不是画到"数据里最后一个时间戳": 数据里那个时间戳是**上一次
变化**的时刻, 而效果从那以后一直在。画到最后一个时间戳会让"她已经冷了 40 分钟"
看起来像"她 40 分钟前冷过一次"。

### 3.3 时间轴的三条泳道

```
        ├──────────┤  计划表(她打算做的)
  ──────────────────────────────  ← 轨道 / now
        ▲     ▲          ▲       感官(必须现在处理的)
  ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒          持续影响(一直在的)
```

泳道的顺序是有理由的: 计划在上(那是她要过的日子), 感官针贴着轨道(那是打断它的
东西), 持续影响在最下面铺满(那是所有事发生时的背景)。**感官针在最靠近轨道的地方**,
因为打断和被打断的节奏才是这一屏真正要讲的那件事。

### 3.4 认不出的类型不许变成针

`classifyEvent()` 对**没有登记**的类型返回 `['fact']` —— 它落到 `facts` 列表, 而不是
被画成某一种形状。理由: 认知链新加一种事件时, 前端不该用猜的方式决定"它要不要马上管"。
猜错的方向是**危险的那一个**(把一条慢效果画成必须立刻处理的针)。所以新类型的默认
归宿是"知道自己不知道"。

### 3.5 落到实现

纯函数与它们所在的文件(全部被 `src/pages/agent/agent.test.ts` 钉住):

| 函数 | 在哪 | 它钉住的一件事 |
| --- | --- | --- |
| `sortByStart` | `pages/agent/Plan.tsx` | 没有开始时间的排在最后, **不是**开头 —— 排在开头会让"认不出时间"看起来像"很早就开始了" |
| `isNow` | `pages/agent/Plan.tsx` | 半开区间 `[start, end)`: 相邻两条计划的接触点**不同时**算"现在" |
| `buildOverlays` | `pages/agent/Today.tsx` | A 类带子铺到 `now`; 同一类型变化两次保留为两条**相接**的带子(合成一条会让"她 10 点加了衣服"和"她 11 点又加了"看起来是一次); 认不出的类型**永远不成针** |
| `classifyEvent` | `lib/events.ts` | 未登记的类型返回 `['fact']` —— 见 §3.4 |

`buildOverlays` 落在页面文件里而不是 `lib/` 里, 是因为它的返回值直接就是一组 React
要画的东西(形状 + 位置 + 文案); 把它抽到 `lib/` 会为了"纯"而多一层没有第二个人用的
中间类型。它能被测试的原因不是"它在 lib 里", 而是它**只吃数据、不吃 props**。

## 4 计划变更怎么画 —— 版本链

### 4.1 三种被明确否决的画法

产品原话: 打断一条正在进行的计划事件, **不是**"更新剩余时间、立刻插入新事件、然后恢复
原来的"。所以下面三种都不是本设计的备选:

| 否决的画法 | 它错在哪 |
| --- | --- |
| 暂停/恢复 + `remainingDuration` | 她的计划表里从此有一条"剩 23 分钟"的作业 —— 而她脑子里那条作业已经被她重新安排过了 |
| 原地编辑, 把 `end_at` 往后推 | 时间轴上看着对, 但"她为什么把作业推后了"这件事没有留下 |
| 插到最前面再恢复 | 界面上唯一的证据是一次闪烁 |

正确的形状是: 它**真的改了计划板**, 而她**重新想了一遍**。

### 4.2 正确地画: 修订链

`PlanRevision` 与 `PlanMutation` 是这个产品里最值得好好画的一对数据:

```
修订 #7   ← 当前
  previousRevisionId → #6
  mutations:
    MOVE    作业      12:00–13:00  →  12:40–13:40
    INSERT  穿衣服    12:00–12:40
  reason:   "外面变冷了, 先加衣服"
```

界面上它是一条**纵向的链**, 每一环的 `previousRevisionId` 指着上一环。规矩:

1. **链只往后加, 不删。** `revisionHistory` 永不被删除, 所以界面上也永远不提供
   "只看最新"以外的裁切 —— 一个能被折叠掉的修订链等于一个能被静默改写的历史。
2. **每一环画的是"相对上一环的差", 不是"改完之后的全量"。** 全量摆七份的后果是
   七屏几乎一样的时间轴, 而真正的信息(那三次移动)要人去逐行比对。
3. **`reason` 必须原样显示, 不做摘要。** 那句话是认知链自己写的, 也是唯一能回答
   "她为什么这么改"的东西。

### 4.3 被打断的那一条去哪了

这是最容易画丢的一件事。一条被打断的计划有三种下场, 界面上必须是**三种不同的样子**:

| 下场 | `PlanMutation` | 界面 |
| --- | --- | --- |
| 往后挪 | `MOVE` | 同一个标题出现在新位置, 旁边一个小箭头标着"从 12:00 挪来" |
| 被换掉 | `REPLACE` | 旧标题**划掉**并在原位留一枚灰色的壳, 新标题在它旁边 |
| 不做了 | `REMOVE` | 原位留一枚灰色的壳, 标注"12:20 取消了" —— **不消失** |

"不消失"是这一节的结论: 一条计划从时间轴上被抹掉, 和一个计划从来没存在过, 在界面上
必须是两件事。她能决定"今天不写作业了", 而那个决定本身是这一天的内容。

### 4.4 「立刻执行」就是触发时间设成现在

没有第五种操作。用户想"现在就做", 结果就是一条 `MOVE` 到 `now` —— 与"她想先穿衣服"
走的是同一条路。UI 上不给一个叫"立即执行"的特殊按钮, 因为它会诱使实现长出一条
平行的时间轴语义。

### 4.5 为什么是左右并排, 不是上下

"改前 / 改后"两栏并排: 上下排列时两条时间轴的刻度对不齐, 而"作业从 12:00 挪到了
12:40"这个判断靠的正是**同一列上的两个位置**。

## 5 事件流怎么画 —— 三类形状不同

### 5.1 形状(与 §3.2 同一套)

`/events` 上的每一条按它**属于哪几个类别**画形状。一个事件可以同时属于两个类别
(一件事可以既一直在生效, 又需要立刻被感知) —— 所以界面上的"形状"是一个**集合**,
不是一个单选值。

图例是可点击的过滤器(`aria-pressed`), 而不是装饰。过滤语义是**交集**: 一个同时属于
A 与 B 的事件在"只看 A"时仍然保留。

### 5.2 排序

新的在上; 没有时间的排在最下面。`timeOf` 对没有时间的返回 `-Infinity` ——
一个认不出时间的条目排在顶上, 会让人以为"刚刚发生了一件不明的事"。

同一毫秒的两条不许用 `type` 或 `at` 做 key: key 是 `${type}@${at ?? '?'}#${i}`,
`#${i}` 那一段是必需的, 否则同毫秒的两条会互相顶掉一条。

### 5.3 不聚合

产品原话: 通知她的事件**一条一条**地通知, 像微信/QQ, 从不合并。
`/events` 这一页是同一件事的读面 —— 所以它也不聚合。这不是排版选择, 是**忠实**:
一页把 200 条压成"12 条同类事件"的界面, 会让人以为系统就是这么处理的, 而它是
一条一条递过去的。

### 5.4 载荷只给字段摘要

`summarizePayload()` 输出的是"这个载荷有哪些字段、各是什么类型", **不是正文**。
理由见 §8: 消息正文只在她自己去看手机那条路上出现, 而事件流不是那条路。

### 5.5 `/runtime` 唯一能看见正文的地方

`Runtime.tsx` 的 `PendingPanel` 是**整个控制台里唯一**渲染消息正文的地方
(`PendingMessage.content`)。页面上写着理由: 那条消息是**她本人已经读过并选择推迟**的,
所以它已经不是"还没被感知的信息", 而是"她决定晚点处理的信息" —— 前者不该出现在任何
运维界面上, 后者是运维唯一需要看的东西。

它默认折叠, 要一次显式点击才展开。

### 5.6 影子对比: 只认肯定的 `true`

`shadowVerdict()` 在 `enabled` 或 `shadow` **显式为 `true`** 时才说"在跑"。
`{}` 与 `false` 读出同样的结果(未知)。

理由: 影子对比这一屏上的所有数都是 0 —— 而 0 有两种意思, "没测"和"没有分歧"。
把"服务端没说它在跑"读成"在跑", 会让一次基于空数据的切流决定看起来是有依据的。
所以判定是**肯定式**的: 只有明说在跑才算在跑。

## 6 关系网怎么画

### 6.1 她的通讯录是她自己长出来的

产品原话: 她的通讯录是通过聊天**自己长出来的**, 不是从平台同步的。

这句话在界面上的第一个后果是: 关系网这一页**不能**是一个"平台用户列表 + 关系字段"的
表格。那个形状说的是"平台有一份人名单, 每个人身上挂着她对别人的看法"; 事实是反过来的
—— 名单是她聊出来的, 一个没聊过的人根本不在她的世界里。

页面上写着这一条, 因为这是最容易在实现里被反转的一件事(平台有全部用户, 顺手就能列)。

### 6.2 两组数字必须分开

| 组 | 是什么 | 会不会错 |
| --- | --- | --- |
| **关系维度** | 她自己的内部状态(信任、亲近、张力…) | **会** —— 她的判断可以不准 |
| **Reality Ledger 投影** | 账本, 实际发生过什么(读过几条、推迟过几条) | 不会 —— 它是已发生事实的计数 |

两组数并排摆着而**不合并**, 因为它们矛盾的时候才是信息量最大的时候: 她以为跟这个人
很熟, 而账本上说她把他发的 8 条全推迟了。合并成一个"亲密度"分数会把这件事抹平。

`readDimensions()` 是纯函数: 顶层与 `relationship` 下嵌套两种形状都认(嵌套的赢),
已知的键给中文标签与"高的那端是好还是坏", 没登记过的键**保留并标注未登记** ——
认知链新加一个维度时, 界面上会多一行标着"未登记"的量, 而不是静默少一行。

`tension` 与 `connectionPressure` 是 `goodHigh: false` —— 这两条高反而是坏事。
把方向搞反的后果是一位数之差被读成了相反的意思, 而屏幕上没有任何东西会提示。

### 6.3 认识阶梯

`AwarenessOutcome` 用**一条堆叠条**画读/推迟/忽略, 因为三段加起来是一个整体
(她收到过的全部)。分成三个独立的数会让人以为它们是三件独立的事。

### 6.4 边界: 缺口写在页面上

没有 `RelationshipGraph` 端点, 也没有"账号绑定"的读面。两处 `GapNote` 直接印在页面上
——**不是**做成一个灰掉的按钮。一个灰按钮说的是"这个功能还没做", 而页面上那行字说的是
"这个数据现在取不到, 原因是 X" —— 后者才是运维需要的信息。

## 7 手机与设备怎么画

> **诚实标注:** 这一节是**规范**, 不是"已经画出来了"。电量、应用列表、四个声道的音量
> 在当前这一版里**读不到** —— `phone/` 包(11 个类)没有任何 HTTP 出口, 手机页上相应
> 的位置是 `GapNote`(见 §12 G3/G4/G5)。下面写的是这些数**一旦有了**该怎么画,
> 以及为什么不能画成另一个样子。把"还没画"和"该这么画"分开写, 是因为一份设计文档
> 最容易被误读的地方就是这两者的区别。

### 7.1 手机不是"一个页面", 是她的一个世界

V2.2 把世界劈成两半: **数字设备世界**(她能动, 通过技能/工具/MCP 暴露)与
**数字世界**(她不能改, 环境自己从她所在地拉真实天气给她感知)。

界面必须让这条边界**看得见**: 手机页上的每一项都是**能改的**(音量、应用开没开、
免打扰), 而身体页上的天气、温度是**只读的**。两页上同样的一个数值, 一页可以拖、一页
拖不动 —— 这件事本身在教学。

### 7.2 音量是四个通道, 不是一个滑块

`AudioSystem` 四条通道: `NOTIFICATION` (0.6)、`RINGTONE` (0.8)、`ALARM` (0.9)、
`MEDIA` (0.7)。各自的默认值不同, 这个不同是有意义的: 闹钟默认最响, 通知默认最轻。

界面上**必须四条分开**。合并成一个"音量"滑块之后, 有一件事就再也表达不了了:
"她的通知很轻, 但闹钟能把她叫醒" —— 而那正是她被设计成的样子。

### 7.3 音量是连续值, 不是枚举

`AudioVolume` 是一个 0–1 的 double, **刻意不是**枚举。界面画成滑块, 不画成
"静音/小声/正常/大声"四档: 四档会让"我把通知调小了一点点"变成一次跨档, 而跨档是
一个离散决定 —— 她那边收到的却是一个连续值。

### 7.4 免打扰是两层, 界面上也摆两层

| 层 | 住在哪 | 决定什么 |
| --- | --- | --- |
| 第一层 | **聊天平台**(`ConversationNotificationSetting.muted`) | 要不要**发出**那条通知信号 |
| 第二层 | **她的手机**(`NotificationPolicy`) | 信号到了之后**怎么响** |

这一条在仓库 1 的会话设置面板里也写着(同一件事实, 两个站点各写一遍, 因为用户会在
两个地方分别撞上它)。还有第三种"她没反应": 她**自己在做什么**(睡着了、专注在一件事上)
—— 前两种是设置, 第三种是状态。三种原因完全不同, 所以不能当成同一件事去调。

## 8 聊天怎么画 —— 消息正文只在"她自己去看"那条路上

### 8.1 这一条是整个产品最硬的规则

产品原话: 她收到的通知**不带消息正文**; 只有当她**自己做出"看一眼手机"这个动作**时,
才去调聊天平台的接口拉会话列表与聊天记录。

它在界面上产生一个可检查的约束:

> **控制台里任何时候都不许主动把消息正文摆出来。**

因为一旦有一处这么做了, 整个设计就退化了: "通知不带正文"从一条**架构**约束变成了
一条**懒惰**的实现(反正控制台会显示)。她"看不看手机"这个动作也就没有代价了。

### 8.2 三个能看见正文的地方, 各有各的理由

| 地方 | 是什么 | 为什么允许 |
| --- | --- | --- |
| 仓 1 的聊天室 | 用户自己发的、自己看的会话 | 那是**用户自己**的聊天软件, 与她无关 |
| `/runtime` 的 `PendingPanel` | 她**已经读过并选择推迟**的消息 | 它已经不是"未被感知的信息", 而是"她决定晚点处理的信息" |
| 仓 2 的 `archive` 页 | 原始返回体 | 调试用, 收敛到最后一个标签页 |

事件流(`/events`)与"今天"页**不在**这个名单里。

### 8.3 她的电话簿

她的联系人是她自己聊出来的(§6.1)。控制台上没有"给她加一个联系人"的入口 ——
那个入口一旦存在, 通讯录就变成平台同步的了。

## 9 交互与视觉规范

### 9.1 颜色

**全局只有一个强调色**: 电光蓝 `#2563EB`(暗色下提亮到 `#3B82F6`, 同一个蓝在近黑背景上
对比度不够)。三类事件色、`ok`/`warn`/`danger` 之外不再引入任何色相。

三类事件的色相**故意拉得比 `accent` 与 `ok` 之间更开**, 因为它们不是并列的状态, 是三种
不同的紧迫度:

| token | 亮色 | 暗色 | 含义 |
| --- | --- | --- | --- |
| `cat-effect` | `161 98 7` 琥珀 | `253 224 71` | A 持续影响 —— 慢, 但一直在 |
| `cat-sensory` | `225 29 72` 玫红 | `251 113 133` | B 实时感官 —— 必须现在处理 |
| `cat-schedule` | `124 58 237` 紫罗兰 | `167 139 250` | C 计划表 —— 属于时间轴 |

值写成 `R G B` 三段而不是 `#hex`, 因为 Tailwind 的 `<alpha-value>` 要往里插透明度 ——
写成 hex 的话 `bg-accent/10` 这类写法会**静默失效**。

### 9.2 字号与间距

- 正文 `text-sm` (14px); 说明性文字 `text-xs` (12px) 与 `text-[11px]` 两档
- 时间戳、ID、计数一律 `.tnum`(等宽数字)。这一条在控制台比在聊天端值钱得多:
  一屏全是 agent id、时间、计数, 比例数字会让整张表在**每次轮询刷新时左右抖**
- 面板内边距 `px-4 py-3`; 面板之间 `space-y-4`; 页面 `px-3 py-4` 起, `sm:` 起 `px-6`
- 侧栏小屏折叠为图标 + 分隔线, `md` 起显示分组标题

### 9.3 圆角 / 边框 / 阴影

- 圆角: `rounded-lg` (8px) 用于控件, `rounded-xl` (12px) 用于面板
- **页面上的卡片一律靠边框, 不靠投影。** `shadow-pop` 是全局唯一的阴影, 只给浮层用
- `raised` 在亮色下与 `surface` 同色, 靠边框区分 —— 高级感来自边界, 不来自色块

### 9.4 深色模式

`<html class="dark">` 由 `index.html` 里一段内联脚本在**首屏渲染前**写上, 之后由
`stores/theme.ts` 维护。内联脚本这一段是必需的: 放 React 里会在首屏后闪一下白。

默认亮色是产品决定 —— 没选过主题的用户、以及任何读不到 `localStorage` 的场景
(无痕、首屏脚本失败)都该落到亮色。

### 9.5 空 / 加载 / 错误

三种状态各有各的规矩:

| 状态 | 规矩 |
| --- | --- |
| 空 | 说清是"还没发生"还是"不该有"。`empty` 是每个 `SectionSpec` 的必填项之一 |
| 加载 | **不用骨架屏**。这一层的加载是"某几块就绪了、某几块没有", 骨架屏整屏一起闪 |
| 错误 | `describeError()` 把 `ApiError` 翻成人话, 并把状态码与端点**一起**显示 |

错误必须带端点: "读关系叙事失败"和"读关系叙事失败(500 GET /api/relationships/narrative)"
对排查的人是两条消息。

### 9.6 文案

- 界面、注释、文档一律中文
- 技术标识(路径、字段名、状态码)不翻译, 用等宽字体
- **数字不许说谎**: 一个数是 0 的时候要说清"没有"还是"没测"(§5.6)

### 9.7 动效

只有 `fadeUp` 与 `fadeIn` 两条 keyframes, 时长 150ms 的默认过渡。没有位移超过 8px 的
动画 —— 这个控制台上"东西在动"的意思应该是**数据变了**, 不是**界面在表演**。

## 10 无障碍

### 10.1 键盘可达

- 每一个可点元素都是 `<button>` 或 `<a>`, 没有 `onClick` 挂在 `<div>` 上
- 浮层可 `Esc` 关闭, 打开后焦点进到浮层内
- 过滤图例是 `<button aria-pressed>`, 不是带颜色的 `<span>`

### 10.2 对比度

正文 `ink` 在 `surface` 上亮色 15.9:1 / 暗色 16.4:1;`ink-soft` 不低于 7:1。
`ink-faint` 只用于**辅助信息**(时间戳、单位), 不承担必须读到的内容。

### 10.3 读屏

- 开关是 `role="switch"` + `aria-checked`, 不是美化过的 checkbox —— 读屏报"开/关"
  而不是"已勾选/未勾选", 而这两个开关切换的是**一件一直在生效的事**
- 开关旁边那行字是**视觉**标签, `aria-label` 才是读屏听到的(它要说清"哪一段对话的")
- 纯装饰(划掉铃铛的那道斜线)一律 `aria-hidden="true"`
- 时间轴给一段读屏可读的文字摘要, 因为图形化的时间轴对读屏是不存在的

### 10.4 不只靠颜色

这是三类事件编码的**首要约束**(§3.2): 形状(带 / 针 / 条)承担区分, 颜色是第二位的。
一个色盲用户看到的仍然是三种形状; 一个把颜色看错的用户看到的三条时间轴仍然是三条。

同理: 未读不是只用一个红点,"免打扰"不是只用一个变灰的图标 —— 后者同时有位置说明文字。

## 11 性能预算

### 11.1 首屏

| 指标 | 预算 | 现状 |
| --- | --- | --- |
| 主包 (gzip) | ≤ 150 kB | 138 kB |
| CSS (gzip) | ≤ 12 kB | 5.7 kB |
| HTML (gzip) | ≤ 1.5 kB | 1.1 kB |
| 首屏可交互 | ≤ 1.5 s (4G, 中端机) | 待实测 |

没有路由级代码分割:**整个控制台比一张图片还小**。在 138 kB 上做 `React.lazy` 只会用
一次额外的网络往返换一个用户感觉不到的差。这条预算的作用是**未来**——超过 250 kB
时再讨论分割。

### 11.2 轮询 vs SSE / WebSocket

这一条要分页面回答, 因为答案不一样:

| 页面 | 机制 | 理由 |
| --- | --- | --- |
| `/runtime` 的指标与轨迹 | **轮询**, 5–10s | 它是一屏计数, 没有人盯着它等某一秒 |
| `/runtime` 的排程 | 轮询, 30s | 变化以分钟计 |
| `/events` | **轮询**, 3s | 见下 |
| 「今天」的时间轴 | 轮询, 15s | `now` 那条线的位置由客户端算, 不需要服务端推 |
| `/agents` 列表 | 轮询, 30s | |

**为什么 `/events` 是轮询而不是 SSE。** 直觉会选 SSE: 事件流天然是一条流。三个理由
让它落在轮询上:

1. **端点不支持。** 现在没有 `GET /api/v10/events/stream`。而"事件流"这个读面
   (`GET /api/v10/events?since=&type=&limit=`)本身也已经是一个**滚动窗口**的形状 ——
   它天生适合 `since` 增量拉。
2. **不需要**。看她的人不需要 200ms 的延迟; 需要低延迟的那个东西是**她**, 而她的
   通路是 `EventFabric` 与聊天平台的长连接, 不是浏览器。
3. **认证更简单**。SSE 走同一个 nginx server 块, 但长连接要单独考虑超时与缓冲
   (`proxy_buffering off`), 而在 `/api/**` 不套 Authelia 的前提下一旦配错, 症状是
   "连上了但不发数据"—— 一个比"每 3 秒问一次"难查十倍的故障。

`since` 用**上一次响应里最新一条的时间戳**, 不用客户端时钟 —— 客户端时钟差 3 分钟会
让增量拉变成一个每次都全量拉。

**将来切 SSE 的判据**: 如果出现一个"用户盯着看、事件到达要立刻可见"的场景(例如
实时调试), 那时候加 SSE, 并且是**新增一个端点**, 不是改这一个。

### 11.3 轮询的公共规矩

- 页面不可见时停止(`document.visibilityState`) —— 后台标签页不该占带宽
- 请求失败不叠加: 一次失败退避到 3× 间隔, 成功即恢复
- 同一端点在同一时刻至多一个在飞的请求

### 11.4 时间轴渲染

时间轴上的条目数按"一天"量级(几十条)。**不做虚拟化** —— 虚拟化在这个量级上带来的
是"滚动时条目闪一下"这种真损失, 换来的是一个不存在的问题。

#### 缺口的呈现方式

上面每一条在对应的页面上都是一个 `GapNote` —— **不是**一个灰掉的按钮。理由:

> 一个灰按钮说的是"这个功能还没做", 而页面上那行字说的是"这个数据现在取不到, 原因是 X"。
> 后者才是运维需要的信息。

全仓共 **17** 处 `GapNote`, 分布在 `Relation.tsx`(2)、`Plan.tsx`(2)、`Body.tsx`(3)、
`Phone.tsx`(2)、`Today.tsx`(2)、`Events.tsx`(4)、`Runtime.tsx`(2)。

**另有一条不是缺口、是约定**: `/api/**` 路径**不套 Authelia**(三方机器客户端要 401
不要 302), 静态页套。浏览器的 XHR 如果被 302 到登录页, 会表现成"登录了却连不上后端"。
Service Worker 会缓存旧的 302 —— 遇到过就把 `sw.js` 404 掉、XHR 改返 401。这条**不许
被重新引入**。
